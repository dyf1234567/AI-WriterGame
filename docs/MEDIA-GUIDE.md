# 添加图片、视频与表情包

2026-10-23。真实模式使用聊天模型理解请求并选择实际分类 / 文件，服务端验证后在发送时绑定。旧版问题及本轮处理见 [媒体检查报告](MEDIA-REVIEW-2026-10-23.md)。

## 放在哪里

```text
static/
  images/npc/郭瑞莹/练琴/琴房练习01.jpg
  images/npc/郭瑞莹/露营/湖畔帐篷.webp
  videos/npc/郭瑞莹/练琴/夜间钢琴.mp4
  videos/npc/郭瑞莹/露营/篝火.webm
  stickers/开心/好耶.gif
```

人物文件夹名必须与游戏内姓名相同；添加人物文件夹不会创建游戏角色。图片、视频可以使用相同分类，也可以递归分多级目录。旧版直接放在 `videos/npc/人物名/` 下的视频继续可用，默认归入“日常”。旧版 `images/npc/人物名.jpg` 等扁平人物图仍可作为自拍后备，同等匹配时优先选择分类目录内的图片。表情包可以放子目录。

图片支持 jpg、jpeg、png、webp、gif、svg；视频识别 mp4、webm、mov、m4v。实际播放取决于浏览器和文件编码；优先使用 MP4（H.264 视频与 AAC 音频）或浏览器支持的 WebM。不能只修改扩展名。emoji 直接输入文字即可，不用添加文件。

## 什么时候生效，怎样触发

1. 复制新文件或创建新分类，无需重启服务。后端每次发送会重新扫描目录；图片和视频下次发送即可参与匹配。
2. 要在表情选择面板看到新文件，点击 **设置 → 刷新本地素材**，或面板里的 **刷新素材**。刷新页面也会重新读取清单。
3. 在与对应人物的短信中明确提出，例如“发一段练琴视频看看”“发张露营照片”。真实模式按语义选择清单里的分类或文件；例如“听老师讲课的照片”可以对应“上课”，不必穷举别名。演示模式没有语言模型，仍使用明确触发词和文字匹配。
4. NPC 也可在回复中主动分享。是否分享由聊天上下文决定；文件出现并不意味着每条消息都会触发附件。

## 怎样匹配

真实模式的流程是：**扫描本人物素材 → 把实际分类、说明与候选文件提供给聊天模型 → 模型结合当前消息和最近聊天选择引用 → 服务端验证并保存附件**。回复与素材选择合并在原有的一次聊天请求中，不另发一次选择请求。

模型先判断是否需要发附件。“你今天上课了吗”属于询问，不因包含分类名就发图片；“录一小段听讲的情况”要选择视频；“不要上课的，看看午饭”要排除上课；“同个场景换一张”“把刚才那张再发一次”可参考最近聊天中的附件编号。

图片、视频的所有实际分类完整列出，取消原先每种类型 300 字的分类截断。为控制上下文体积，每类图片 / 视频展示最多 4 个文件示例，表情每类最多 12 个；优先按当前请求的文字相关性选示例，并保留该类最近发送的一个文件，便于明确重发。模型可只选择分类，服务端从整类文件中优先避开最近十条消息已发的素材；若指定具体文件，则按该文件发送，不自行换成另一张。请求具体画面时，模型应选择有说明支持的示例，不能猜测未展示文件内容。

服务端检查角色归属、媒体类型、分类与文件是否一致、文件是否在本次候选清单、模型给出的排除分类，以及原话里可明确识别的否定和类型要求。无效编号不能退回随机文件；`media=[]` 明确不发，旧标题和关键词都不能补发。不匹配时模型可不附附件并自然说明；若仍返回无效引用，界面显示“暂无匹配素材”。这些验证不能代替模型对复杂语句的理解。

演示模式以及未遵守新协议、仍只返回旧标题的兼容模型，继续比较请求或标题与目录分类、文件名、说明和标签，使用原有“钢琴 / 琴房 / 练琴”等内置词组。别名对此仍有帮助；这条兼容路径没有完整语义理解能力。

文件 ID、URL、分类和说明随消息保存，重绘、重新打开会话和添加新素材不会重新抽取旧消息。旧消息首次继续游戏时完成一次绑定；无法恢复过去未保存的随机选择。删除或移动已发送文件会让旧消息显示缺失提示；扩充时保留旧文件路径，替换内容建议使用新文件名。

## 自定义别名和说明

类别名本身足够明确时，不用配置。真实模式的别名是可选补充；更推荐用一句自然语言说明该目录的内容。在同一目录加 `_category.json`：

```json
{
  "description": "湖畔露营的生活记录，包括搭帐篷、夜晚围坐篝火。",
  "aliases": ["篝火", "帐篷", "野营"],
  "tags": ["湖畔", "夜晚"]
}
```

针对一条视频，可添加同名附加配置 `篝火.mp4.json`：

```json
{
  "caption": "湖畔露营时拍下的篝火",
  "description": "夜晚的湖边，帐篷旁燃着篝火；没有人物正脸。",
  "tags": ["篝火", "露营", "帐篷"]
}
```

例如新建“上课”目录，可以用 `{"description":"课堂记录：老师授课、听讲和记笔记。"}`，不用列完所有近义说法。文件名是数字也可以通过目录说明选择整类；想精确选中某张黑板图或某段讲课视频，就在对应文件的附加配置里写清具体内容。

文件配置覆盖同文件夹配置里的同名字段；配置只读取文件直接所在目录，不逐级继承祖先目录。图片、视频目录分开读取，需要时分别配置。支持普通 UTF-8 和 Windows 常见的带 BOM UTF-8。修改说明、别名或文件后，下次发送自动读取，无需重启。

配置只提供素材描述，不是剧情指令。表情名称来自文件名；选择面板传文件 ID，因此 `哈哈.jpg` 与 `哈哈.svg` 可以分别选择，带单引号的文件名也能发送。NPC 回复表情可选择清单里的新文件，不再限于写死的表情名称。

## 实际边界

本阶段是**聊天模型对文字资料的语义选择**，没有安装向量模型，也不会自动观看视频、识别图片或生成说明。把所有文件命名为 `001`、放在“日常”里且不加说明，模型无法知道每个文件的具体内容。模糊表达、否定、指代的理解效果取决于所接聊天模型，不能保证每句都选对。

单类文件很多时，只有部分文件示例进入提示词，示例筛选仍是文字相关性排序，可能漏掉只在意思上相关的具体文件。全部分类和示例也会占用输入上下文，分类极多时需要下一阶段的语义索引 / 分层检索；当前没有自动调用 embedding 接口。将来可对新增和修改的素材生成、缓存内容描述与语义索引，而不必每次聊天重新分析整个库。

附件的标题、说明、分类和标签进入聊天回忆检索；这些资料不能成为玩家的承诺、约会或已完成事件。正文和表情同时发送时，两者都进入本次聊天上下文。聊天保持一次模型调用；清单和选择结果会增加输入输出 token，素材扫描本身不调用模型。测试用模拟模型验证协议与绑定，未调用付费接口验证某款模型的理解准确率。

图片和视频损坏、格式不支持或文件被移除时，界面会给出提示。文件存在与格式扩展名正确并不代表浏览器一定能够解码。
