# 图片、视频、表情包与 emoji 检查及扩展方案

检查日期：2026-10-23。检查的媒体版本：`06da1f7`，同时核对上一提交 `7eab2a1` 的商城更新。本轮媒体代码为只读审查；地图风格与类型筛选按用户追加要求另行修改。

## 当前使用逻辑

`本地素材目录 → /api/photos 扫描 → 浏览器缓存清单 → 聊天决定附件类型及标题 → 保存消息 → 前端随机挑文件展示`。

模型目前只写标题或表情名称，不生成图片、视频，也不理解本地图片像素或视频内容。图片和视频的实际文件在展示时选择，消息里没有固定素材 ID，这是历史附件不稳定的根源。

| 类型 | 文件位置 | 现有选择方式 | 发送入口 |
| --- | --- | --- | --- |
| 图片 | `static/images/npc/人物名/分类/文件` | 标题关键词匹配分类，再随机选图；缺失有占位图回退 | NPC 短信与朋友圈 |
| 视频 | `static/videos/npc/人物名/文件` | 同一人物目录随机选，标题不参与具体视频匹配 | NPC 短信 |
| 表情包 | `static/stickers/文件` | 文件名去扩展名即名称，精确／包含匹配，缺名时随机 | 玩家面板与 NPC 短信 |
| emoji | 不需要文件 | 普通 Unicode 文本，由输入法或模型写入正文 | 玩家与 NPC 文字 |

图片支持 SVG/JPG/JPEG/PNG/WebP/GIF；视频扫描 MP4/WebM/MOV/M4V；表情扫描 SVG/PNG/GIF/JPG/JPEG/WebP。清单在页面初始化时拉取；新增文件通常需要刷新页面，无需重启后端。视频目录是人物下一层直接放文件，不会递归扫描分类子目录。

## 已复现的媒体问题

### 1. 历史图片和视频会在重绘时更换（P2）

`npcPickPhoto`、`npcPickVideo` 在每次展示时随机选择；`renderChatBody` 重建全部气泡。发送新消息、显示“正在输入”、重开会话时，同一条旧消息可以换成另一张照片或另一条视频。播放器也会重建，播放位置丢失。

应在发送时确定素材 ID 并持久保存，展示阶段只读取，不再随机；聊天更新应保留既有播放器节点。

### 2. 表情名称被拼入可执行脚本（导入外来素材时优先级 P1）

`toggleStickerPanel` 将名称拼进内联 `onclick`。普通名称 `it's fine` 已会造成语法错误；构造的合法本地文件名还能使属性解码后执行额外语句。已用无网络的探针验证执行，不是只推测转义不足。

应使用 `data-sticker-id` 与事件委托，不把素材名称拼接成 JS 源码。

### 3. 表情包名称会变成正式承诺（P2）

后端将“（表情包：名称）”传给正式记忆登记，且不验证名称是否来自素材库。发送名为“我答应明天晚上七点琴房见你”的表情，实际建立承诺事实和待办预约。

应验证素材 ID，并把附件情绪说明与玩家明确说出的承诺分开；表情本身只能提供语气，不能授权约定或任务结算。

### 4. 表情面板可能永久显示空库（P2）

初始化未等待清单加载，面板第一次打开即缓存“已加载”。先打开空面板，随后清单成功，再次打开仍不重绘，直到刷新整页。

应区分加载中／空库／失败，清单变化后刷新面板，并提供手动重载。

### 5. 同名不同扩展名导致点选与发送不一致（P2）

同时放 `哈哈.jpg` 与 `哈哈.svg`，面板显示两张，发送仅保存名称“哈哈”，展示永远取第一个同名文件。点击第二张也不会发出所选那张。现有表情 README 建议保留同名占位 SVG，恰好会遇到。

应让文件具有独立 ID，或者清单构建时明确同名替换优先级。当前替换占位素材时应避免保留同名不同格式的重复项。

### 6. 当前消息与长期记忆的媒体语义不完整（P2）

- 文字“谢谢你”加“哭哭”表情时，当前模型只收到文字；下一轮最近聊天才包含表情。
- 旧消息 `text=给你看看, video=钢琴排练失误的片段`，追加 50 条寒暄后仍保存在历史，但检索只按 text，无法凭“钢琴排练失误”找回视频说明。

应把文字及附件说明一起组成当前聊天上下文；长期检索同时包含附件标题、标签和发送人。只用说明参与记忆，不把未经理解的媒体内容认定为新事实。

### 7. 明确索要视频也可能收到随机自拍（P2）

演示分支先做小概率照片判断，只有没照片才判断视频。固定随机值为 0，输入“发个视频看看”，实际只生成自拍图片，无视频。

应先匹配明确请求的类型，再考虑主动分享；没有对应资源应清楚反馈，不用另一种类型静默顶替。

### 8. 缺资源的提示和混合气泡样式不足（P2）

- 素材库为空时，纯表情消息会显示空白；缺少 `[表情包：名称]` 替代文字。
- 视频没有资源时静默隐藏，失败文件没有清楚的错误提示。
- 文字加表情的整条 NPC 气泡被设成透明，文字仍为深色，深色主题下难读。该样式问题由实际 class 与 CSS 级联确认，尚未单独截图。

应保留附件失效提示、替代文字与重试入口，只对纯表情取消气泡底色。

## 视频及 emoji 的实际边界

抽查现有占位视频：H.264、yuv420p、480×480、3 秒、无音轨，文件编码本身正常。扫描到扩展名不代表浏览器一定能播放；容器和编码是两层。新增素材优先采用 MP4/H.264（有声音时配 AAC），也可提供 WebM 备选；导入时检查编码、时长、尺寸、文件大小与封面。参考 [MDN 容器说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Containers) 和 [video 元素及错误事件](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video)。

emoji 没有独立素材表，也没有专用选择器。可以通过系统输入法输入，Windows 可用 `Win + .`。不同设备的字形取决于系统字体；需要统一外观时，应单独引入带授权的 emoji 图形集，并保留原 Unicode 文本作为可访问说明，不能把 emoji 与剧情事实混在一起。

## 未来扩展建议

先统一素材身份与消息存储，再扩大素材数量：

`素材清单 → 人物/类别/情境/关系条件过滤 → 选择并固定素材 → 消息保存 media_id → 原样展示 → 说明参与记忆检索`。

建议清单示例（设计方案，当前尚未实现）：

```json
{
  "id": "guoruiying.video.piano.001",
  "type": "video",
  "owner": "郭瑞莹",
  "category": "练琴",
  "tags": ["琴房", "排练"],
  "mood": "轻松",
  "url": "/static/videos/npc/郭瑞莹/琴房排练.mp4",
  "poster": "/static/videos/npc/郭瑞莹/琴房排练封面.webp",
  "caption": "排练时录的一小段",
  "alt": "琴房内的钢琴排练片段",
  "duration": 12,
  "conditions": {"met": true, "trust_min": 30},
  "checksum": "素材内容指纹"
}
```

推荐实施顺序：

1. 修复内联脚本拼接、表情语义入账及历史随机换图。
2. 增加稳定素材 ID、同名去重、错误回退与面板刷新。
3. 增加角色专属表情、视频分类、场景标签、冷却和关系／剧情解锁；由后端过滤可用资源，不能只在 UI 隐藏。
4. 再做 GM 素材管理：导入、预览、编码检查、分类标签、上下架和缺失文件提示。玩家上传图片／视频属于新增入口，需要独立消息类型及文件管理，当前文字请求不能代替真实上传。
5. 若接入生成服务，以同一素材清单保存生成结果和任务状态；不要让每次阅读触发重新生成或重新扣费。

## 同期商城更新的两个问题

- GM 合法配置普通 100、其他品质 0，使用稀有或史诗保底后，兜底权重数组长度与四项品质列表不一致，抽奖抛 `ValueError`。
- 先使用史诗保底券再用稀有保底药剂，较弱效果会覆盖较强效果，两件都消耗；应保留更高保底或拒绝无收益使用。
