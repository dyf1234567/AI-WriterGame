## 记忆工程（参考 novel-writer skill 的长篇项目记忆模式，已实现）

四层记忆装配，防止长局失忆（`app/memory.py`）：

1. **滚动摘要**：>30 段时压缩为 ≤300 字摘要（保留因果/关系/伏笔/成长节点），正文归档后移出窗口；
2. **事实账本** `state["facts"]`：承诺/约定/伏笔/秘密的长期事实。两个入口——模型每回合可选申报 `fact_record`（一句话）；压缩时顺带批量萃取（不额外花调用）。每条带 `kind`（承诺/伏笔/事实，由线索词判定，不花模型调用）与 `closed`（了结回合，未了结为 `null`）：
   - **常驻**：未了结的承诺/伏笔以 `★` 常驻提示词，上限 `RESIDENT_CAP = 12`，不随回合推进淡出；普通事实仍只带最近 `FACTS_KEEP_IN_PROMPT = 8` 条。最坏情况账本比旧口径多占约 400 字符（实测占整条提示词 5.5%）；
   - **了结**：模型经 `fact_resolved` 申报已兑现/已揭破条目的原文片段，引擎记 `closed = 当前回合` 并退出常驻——**不删除**，账本留着"这事办过"，否则模型会以为承诺还在。片段归一化后短于 4 字不予认定（防撞上一切）；查无对应则面板明示未记账；
   - **去重**：比对键剥掉标点/空白与（承诺）类尾注，同句换标点不再重复入账；换字（替/帮）属语义差异，代码不合并；
   - **淘汰**：硬上限 60 条，溢出按"已了结 → 普通事实 → 未了结承诺/伏笔"的顺序丢最旧，未了结的承诺不会被流水挤掉。
3. **归档检索**：每回合按玩家行动中出现的实体名（NPC/已探明地点/物品）搜 `story_archive.jsonl`，最近 3 条命中注入提示词（每条截 160 字）；
4. **冲突裁决**（事实优先级）：状态账本 > 事实账本 > 摘要 > 检索片段；检索与账本冲突时以账本为准、剧情明示出入，不得悄悄调和（主持规则15）。

**NPC 淘汰归档**（`data/npc_archive.jsonl`）：名册淘汰生成人物前必须先把完整档案（好感/行事录/关系）落盘，归档写不进去就宁可不淘汰；同名人物再次登场时走**档案恢复**——昔日好感与行事录延续（模型申报的新初始好感不作数），通知写明「旧识重逢」。离场人物在记忆手册第六节可见。**新开局生成并通过校验后，备份旧周目再切换归档**；生成或提交失败保留旧进度，避免串档与失档。

## 2026-10-18 可靠性修正

- 各写操作对完整读取—结算—保存过程加线程/跨进程文件锁，前端提交存档版本，旧页面提交返回409，避免静默覆盖。
- 每次覆盖前备份状态及两份归档，最近50份可在“恢复存档”中回滚；失败时三个文件一起恢复。备份必须有完整标记才能恢复。
- 前台仅返回主角已知NPC与已知人设、关系；后台档案仅供主持。`npc_reveals` 记录正文实际揭示的信息。已确认正文可在“往事回看”阅读。
- 签到按 UTC+8 的服务端日期结算，浏览器直接使用 `server_date`。
- 离线按实际比例保留小数天，不再无条件加一天；生成失败保留待结算时长。尚未加入回合内游戏历法。
- 模型SDK不自动重试；只对明确不支持JSON格式的参数错误降级。请求有总时限与结构校验，鉴权/限流不被误判为JSON兼容问题。
- 物品、装备和签到刷新面板时不重播正文；可关闭逐字显示。无直接数值效果的物品提供“在剧情中使用”，不伪称已经有伤势系统。

**NPC 行事录**（`npc["deeds"]`，每人上限 20 条）：NPC 做过的事全程留档——好感变化缘由、NPC 事件、离线动态、给主角的留言都写入；提示词里的"近期记忆"仍是 6 条窗口，行事录是持久档案并展示在记忆手册每个 NPC 名下。

另：**记忆手册** `data/memory/记忆手册.md`——每次存档后自动导出的人可读文档（主角快照/摘要/事实账本分「未了结／近期事实／已了结」三段/关系网/探明进度）；手写内容会被下次导出覆盖，未探明地点只计数不泄底。导出失败**不阻塞存档且不留日志**，痕迹改由同目录的 `_导出状态.json` 记录（`ok`／`ts`／`turn`／`manual` 路径／`error` 异常类型与文本，成功也写）——手册与存档回合数不一致时，看这个文件即可定位是渲染失败还是根本没跑到导出。
