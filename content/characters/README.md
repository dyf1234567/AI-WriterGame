# 角色卡与对白参考

`cards.json` 为现有 35 名角色提供独立说话方式、在意的事、遇到压力时的反应和聊天示例。前 10 名主要角色另有场景示例。人物身份、已经发生的经历、好感和恋爱状态仍来自游戏存档；角色卡不能改写这些内容。

## 参考了什么

本项目卡片和对白为重新编写的内容，没有搬入上述角色的姓名、故事、秘密或原文。公开卡中的思考标签与状态栏没有进入游戏正文；外部卡附带的系统指令没有作为本项目规则执行。同名公众人物仅是游戏中的虚构演绎，卡内反应不是对真人私下性格的判断。

## 怎么起作用

- 正文按当前点名人物或当前地点的已知角色读取少量反应参考，最多两人，总块不超过 1000 字符。只有话题相关时才带场景范例，避免每次聊天都重复报到表格、耳机等道具。
- 真实短信读取对方的声口和当前关系语气，按本次话题选择少量示例。示例明确标为假设，不是聊天历史；当前消息与存档优先。
- 演示短信使用卡内的短回复，问地点时直接使用当前角色地点。已知礼物、旧约定和正式关系仍先经过原有的事实判断，不因角色卡编出旧事或确立恋爱。
- 好感高不自动选取恋人语气。只有已经确认的关系状态才启用该部分。
- 玩家或 GM 改了姓名、身份、人设时，预设卡不再覆盖新设定，改用实时人设推导声口。
- 卡片内容不会直接写入存档。旧存档可以继续用，读取角色卡不创建事实、约定、任务或人物。

没有增加额外模型请求。真实模式仍使用原来的聊天或正文生成请求，卡片会占用一部分输入上下文。演示模式依然是规则与模板，无法具备语言模型对任意新话题的理解。

## 怎样修改

在 `cards.json` 找到对应 `data.name`，主要修改 `data.extensions.writer_game` 中的内容。

| 字段 | 用途 |
| --- | --- |
| `want` | 角色通常在意什么；已有存档中的具体目标优先 |
| `friction` | 碰到压力、不满或犹豫时怎样反应 |
| `speech` | 用词、句式和接话习惯；不要只堆性格形容词 |
| `relationship_tone` | 初识、熟悉和已确认恋人时的语气差别 |
| `examples` | 假设对白或场景，标明 `channel`、`intent` 和前提条件；场景用 `topics` 限制适用话题 |
| `demo` | 演示模式直接使用的短回复，不能编造已经约好、收到礼物或完成任务 |

比如调整郭瑞莹的 `speech`，可以写“先指出具体问题，熟悉时才轻轻损一句；认真时少解释自己的情绪”，再给一条符合这种说法的对话。不要靠大量固定口头禅和每句反问制造差异。

文件保存后下次生成会重新读取，无需重启。JSON 写错或卡片字段损坏时回退到实时人设，不继续沿用旧缓存。`data.description`、`writer_game.base_role` 和 `data.name` 用于核对当前人物身份；需要让 GM 改后的人设继续使用这张卡，就先同步这些绑定字段，再检查卡内行为是否仍合适。

这不是通用角色卡导入器。直接丢入 PNG、普通 V2 卡或别人的系统提示词不会自动生效；新角色仍需先在游戏中存在，并补齐本项目扩展字段。`first_mes`、`creator_notes`、`system_prompt`、`post_history_instructions` 不会被自动当成游戏开场、事实或系统指令。

## 怎样验收文风

程序回归验证角色绑定、GM 修改优先、上下文筛选和记忆边界。自然程度仍需用所接模型比较连续正文与聊天，不能只凭通过测试或命中套话检测判定。当前没有调用真实付费模型做文风评测。
